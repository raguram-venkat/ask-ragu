# Deviations from SPEC.md

Every change to what SPEC.md says — scope change, design correction, ad hoc decision — logged the moment it's accepted. SPEC.md is amended in the same commit, with the `[D-00N]` marker on each changed line, so the spec stays true and this file keeps the history.

Format:

`- D-00N [sprint-N] <what changed> — <why> — <ADR-000X or task file> — SPEC §<sections amended>`

`sprint-0` = found during planning research, before any code.

---

- D-001 [sprint-0] Webhook no longer indexes synchronously: it verifies, returns 202, and runs sync as an in-process background task with a single-flight lock — GitHub fails deliveries not answered within 10 s, and embedding a large push on 2 ARM cores takes longer — ADR-0005 — SPEC §6, §8, §13
- D-002 [sprint-0] `folder_sibling` edges dropped; tags and MOC notes act as traversable hubs instead of materialized pairwise edges — this vault's folders (00 Meta … 04 Fleeting) encode note type, not topic, and a 50-link MOC would be 1,225 pairwise edges — ADR-0010 — SPEC §7, §9
- D-003 [sprint-0] Eval question set moved from Phase 6 to Sprint 2 — SPEC §12 said "built early" but §16 scheduled it last; questions written after tuning get unconsciously biased toward what already works — sprint-2/task_9 — SPEC §12, §16
- D-004 [sprint-0] Scope addition: minimal web UI, plus basic auth and rate limiting — the project will be demoed on a public URL, so §15's "auth out of scope while single-user" no longer holds — ADR-0014 — SPEC §6, §15, §16
- D-005 [sprint-0] Hosted providers carry a `trains_on_data` flag; training free tiers (e.g. Gemini free outside EU/UK/EEA) disabled by default — sending note snippets to a provider that trains on them breaks the §4 privacy principle — ADR-0009 — SPEC §10
- D-006 [sprint-0] Vault-specific rules: Templates/, .obsidian/, Bases/, Attachments/ excluded; dataview/base blocks, Templater tags and callout markers cleaned; note_type from folder used as a ranking prior — found from the real vault's folder layout — sprint-2/task_3 — SPEC §7, §8, §9
- D-007 [sprint-0] Graph expansion bounded per hop (fan-out cap), not only by a total node cap — a MOC or popular tag floods hop 1 before a total cap ever applies; also, Postgres can't LIMIT inside a recursive CTE term, so the implementation choice is deferred to ADR-0015 — sprint-3/task_3 — SPEC §9
- D-008 [sprint-1] Host-dependent work decoupled from the sprint order: Sprint 1 Tasks 4–6 (HTTPS, deploy key, deploy) wait until an A1 exists; Sprints 2+ develop locally on Docker Compose; a temporary E2.1.Micro runs only an A1 retry loop (sprint-1/task_7) and is terminated once the A1 exists — Oracle had no free A1 capacity in Hyderabad (AD-1) at 2/12 or 1/6 on 2026-10-03, and blocking the project on capacity wastes days — sprint-1/task_7 — SPEC §11, §16
- D-009 [sprint-1] Cost control is now enforced, not just monitored: a tenancy quota policy (`ask-ragu-free-tier-guard`) blocks every compute shape except A1, caps A1 at 2 OCPU / 12 GB, and caps block storage at 200 GB. A1 acquisition strategy: each retry asks for 2/12 first and falls back to 1/6 in the same attempt; a 1/6 instance is then resized to 2/12 by the same runner — budgets only alert after a charge, while quotas refuse to create the resource; asking 2/12 first catches bursts of freed capacity, and the 1/6 fallback fits smaller gaps (fragmented hosts), so time to the first VM is the shortest of the options — sprint-1/task_7 — SPEC §3, §11
- D-010 [sprint-2] Two more sync rules: (1) a change to the index settings in `.env` or to the indexing code forces a full index — `index_state.settings_hash` covers two groups defined once in code, EMBED (`EMBED_VERSION` + chunking + model; part of every note's content_hash, so it re-embeds) and PARSE (`PARSE_VERSION` + folder→type, exclusions, stripped fences; rewrites only changed rows, embeds nothing; a per-note `meta_hash` makes link/tag-only changes visible); (2) when the clone belongs to the system (`VAULT_FETCH=true`, the VM), its working tree is reset to the commit just indexed after every successful sync — settings changes produce no git diff, so an incremental sync silently kept an index built with old settings; and since the indexer reads git objects, the VM clone's files would otherwise stay at the commit it was cloned at — sprint-2/task_8, ADR-0017 — SPEC §7, §8
- D-011 [sprint-2] Syncs are serialized across processes, not just inside the app: `sync()` holds a session-level Postgres advisory lock (keyed by schema) for its whole run; the in-process runner still coalesces triggers — the CLI runs in its own process, invisible to the app's single-flight runner, so two syncs could interleave (duplicate embedding, unique-key errors, `index_state` briefly behind) — ADR-0018 — SPEC §6, §13
- D-012 [sprint-3] Link resolution runs vault-wide after every sync instead of per file at extraction, and collisions (two notes with one name or alias) take a deterministic tie-break (nearest the vault root, then alphabetical path) instead of last-write-wins — a per-file pass misses links in unchanged notes broken or fixed by another note's rename/add/delete, and "last write" depends on indexing order, so a full index and an incremental sync could disagree — sprint-3/task_1 — SPEC §8, §14
- D-013 [sprint-3] Graph expansion runs one SQL query per hop, with the total cap applied between hops, instead of one recursive CTE — a recursive term can't rank across the frontier or skip notes already reached, it scans the whole materialized edge set (31k rows) for every walked row, and it measured 5–10× slower with 8 seeds (p95 220 ms vs 20 ms) — ADR-0015 — SPEC §6, §9, §13, §16
- D-014 [sprint-4] Host is the Always Free E2.1.Micro (x86_64, 1 GB RAM) that already runs the A1 retry loop, instead of waiting for an A1; the runner keeps running beside the stack as an opportunistic upgrade, and the stack moves to an A1 if one ever arrives — no A1 capacity in Hyderabad (single AD) after ~4,100 attempts since 2026-10-03, Pay-As-You-Go failed (card declined), and blocking deploy on capacity stalls Sprints 4–6's "on the VM" checks; the Micro is free and exists, and Postgres + app + Caddy are expected to fit in 1 GB with swap and per-container memory limits (to be measured in sprint-1/task_3, with fallbacks there) — ADR-0020 — SPEC §6, §8, §11, §13, §16
- D-015 [sprint-4] No local-model container: the provider chain serves open-weight models through hosted free APIs only (no-training tiers, ADR-0009), plus, if a timeboxed attempt works, one small self-hosted model in a private Hugging Face Space — 1 GB RAM can't hold even a 0.5B model next to Postgres and the embedder, and the owner chose hosted open-weight inference over waiting for an A1 — ADR-0021 — SPEC §3, §6, §10, §15, §16
